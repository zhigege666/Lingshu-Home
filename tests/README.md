## 自动启动、完整验收和进程重启

先按项目 README 构建 `dist/lingshu-home`。使用包装脚本可以自动启动两个全新的回环实例，分别执行完整模式和免账号初始化场景，再各自停止并重启真实进程，复验同一份数据：

```bash
python3 scripts/validate_http.py --provider sqlite
```

包装脚本在 `.runtime/acceptance-sqlite-<时间>/` 下保存私有数据目录、日志和 `summary.json`，不复用现有实例。也可以用 `--binary` 指定二进制，或用 `--output-dir` 指定一个尚不存在的结果目录。每个阶段的摘要记录退出状态、耗时、实际场景组数和断言数；只有四个阶段全部通过才报告整体成功。

随机测试凭据状态单独存放于系统临时目录下新建的 `0700` 目录，文件为 `0600`。重启复验完成或执行退出时自动清理该临时状态；报告目录不保存凭据状态。包装脚本只停止它自己创建的子进程，保留测试数据和日志供排查。

PostgreSQL 验收使用两个不同的全新专用数据库。在私有环境中配置 `LINGSHU_HTTP_POSTGRES_URL`（完整场景）和 `LINGSHU_OWNERLESS_POSTGRES_URL`（免账号场景），然后执行：

```bash
python3 scripts/validate_http.py --provider postgres
```

这些变量与 Go 单元/集成测试使用的六个 PostgreSQL 变量是不同入口，完整对应关系见下文“Go 集成、Docker 与发布工具”。不要重复使用已完成其他套件的数据库，也不要指向个人实例。

页面场景使用 `expectedRevision`，检查冲突返回 `page_version_conflict` 和当前版本；非法请求不能改变已存页面。筛选绑定、重命名绑定、清空全部视图与绑定都不能修改本地导航。后台数据从独立 `/spaces/{spaceId}/navigation` 读取，真实 dashboard 响应不得回到旧顶层 categories/links。元数据检查区分源修改时间与每次读取时间。

书签场景同时验证 preview/import 的 2 MiB 和 10,000 个链接上限；超过上限的文件不能留下部分导入或推进数据版本。链接创建和更新响应必须与立即读取的全部已存字段完全一致，包括 `updatedAt`；保存重启状态前再次核对这一点。重启场景核对账号、模式、链接全部字段、页面 ID/name/revision/config、本地数据版本和源修改时间，再次验证匿名权限。时间戳不会被测试舍入或忽略。

测试保留服务默认的认证限流。初始化、登录和注册遇到带数值 `Retry-After` 的 `429 rate_limited` 时，会显示等待并遵守该窗口，单次请求最多尝试三次。因此完整执行可能需要两至三分钟；它不会放宽生产策略，不重试业务 CRUD 写入或结果不明的网络请求。

测试使用 `.invalid` 域名，不访问任何被导入的目标 URL，也不使用真实业务书签。浏览器视觉交互、Docker 构建、内存占用和平台安装包不属于此脚本的覆盖范围。PAT、MCP、外部推送和 GitHub Traffic 的协议与权限由 Go 集成测试另行验证；本脚本的能力检查不替代那些功能的执行记录。

## 跨服务重启验证持久化

单独的 `http_smoke.py` 不停止或重启服务；`scripts/validate_http.py` 会管理它创建的子进程。也可以将成功验收时的随机账号和数据标记写入临时状态文件，再由维护者重启**同一个测试实例、保留它的数据目录**，执行复验：

```bash
test_state_dir=$(mktemp -d /tmp/lingshu-http-state.XXXXXX)
python3 tests/http_smoke.py \
  --base-url http://127.0.0.1:5188 \
  --allow-destructive \
  --state-file "$test_state_dir/state.json"

# 在这里停止并重新启动测试服务，继续使用相同测试数据目录。

python3 tests/http_smoke.py \
  --base-url http://127.0.0.1:5188 \
  --phase verify-persistence \
  --state-file "$test_state_dir/state.json"
```

状态目录必须位于系统临时目录下、权限为 `0700`，状态文件以 `0600` 创建，且不覆盖已有文件。文件包含随机测试凭据，不应提交、分享或放入产品数据目录。复验会核对已保存的账号、访问模式、导航条目和布局，并再次检查匿名访问权限；它不会创建新业务内容。验收结束后可清理相应测试实例及其临时状态目录。

失败会返回退出码 `1`，输出失败的操作和 HTTP 状态，不打印密码、Cookie、CSRF token 或完整响应体。数据库可能保留已完成的测试数据；修复问题后，应换用新的空数据库重新执行整套验收。

### 场景、写入与恢复的含义

**表单与焦点。** `browser_chrome_refinement.cjs` 使用独立上下文，在浏览器语言 `en-US` 下分别读取中文、英文实例的界面，验证语言由实例决定。覆盖首页搜索的单一圆角焦点、管理区各类控件、Radix 选择器的键盘/空值/焦点返回、对话框裁剪、内联约束错误、修正后错误状态清除、字符输入保留，以及隐藏文件选择器的真实选择与取消。所有草稿退出，最后严格比较完整页面 DTO（包括 revision）和全部原有链接/分类字段。

**正常折叠与真实预览。** 组合脚本使用 `reducedMotion: no-preference`，并移除 Playwright 默认的 `--hide-scrollbars` 参数，让真实滚动条参与几何检查。折叠阶段按帧读取 `.react-grid-item`、`.lh-grid-scroll`、document 宽高和横向溢出，兼顾完整展开/收起与快速连续点击。预览阶段读取实际 iframe 内的 HomeView、书签与草稿内容；四种内部尺寸为 **2560 × 1440、1920 × 1080、1600 × 900、2560 × 1080**，另测试放大、返回和取消。它保留产品 iframe 的 sandbox，仅从测试进程有界轮询同步 DOM 读取，不为测试启用 iframe 脚本。

**保存与拒绝。** `editor` 验证首页取消不写入、有效保存恰好产生一次页面 PUT、一次明确模拟的 409 后草稿仍在，以及取消后回到已保存配置。`chrome` 通过后台实际控件向页眉和页脚的左/中/右六个位置添加有效文本、链接或项目品牌，保留原内容，保存一次，再检查服务读回和首页实际呈现。两个阶段都没有链接或分类写入权限。

**额外边界。** `validation` 在草稿中填入非法 URL，先切到其他槽，再从关闭的区域切到另一位置；两次保存都必须被前端拒绝，自动回到错误项并聚焦可见 URL 控件，同时保留区域开关和输入值。纠正与取消不写入。随后修改首页外观并使用 Restore，要求控件值和实际外观回到编辑开始时、保存按钮禁用、页面及 revision 原封不动。`grid` 则用真实鼠标缩小收藏面板并移到右侧，经首页编辑器保存一次，检查读回的宽度、位置和高度行为，重新载入后无重叠或页面水平溢出。

**恢复单独计为清理。** 组合流程和网格流程的有效变更必须来自实际 UI 请求；测试只转发其原请求并记录真实响应。结束或失败时，脚本先读最新页面，确认 revision 仍等于本次最后一次成功保存的版本，再用该 `expectedRevision` 发清理 PUT，原样恢复开始时的 `name` 和完整 `config`，包括旧配置中原本缺失的 `chrome` 等字段。恢复不是一次后台 UI 保存测试，也不回退版本号。英文四阶段实际运行中，revision 从 **34** 经两次 UI 保存和一次恢复正常推进到 **37**，原名称和完整旧配置恢复一致。随后验证阶段保持 **37** 不变；独立网格阶段一次 UI 保存推进到 **38**，用该版本恢复后为 **39**，仍完整保留原名称、全部配置以及原本缺失的 `chrome` 字段。

如果出现其他写入者、保存结果不明或清理失败，脚本不会猜测版本、通用删除或重建演示空间；失败状态和差异保留在报告中供检查。最终比较全部原有链接与分类对象，包括其时间字段；仅为比较排序对象，不删除或忽略业务字段。只读阶段不通过清理请求来掩盖意外写入。

### 图标导入、显示、删除与失败处理

`browser_icons.cjs` 通过实际后台控件完成以下操作，并在整页重载后读取首页与后台的真实 `<img>`：

- 内置服务器图标显示为选中草稿，取消表单零写入，原页面、导航和图标库保持一致。
- 上传本次生成的原始 64 × 64 几何 SVG，填写明确的权属说明后导入。单图自动成为当前链接草稿图标；库与图片资源此时已持久化，而链接仍未保存。该步骤不能描述为“所有操作都等到保存链接才落库”。
- 创建本次唯一的测试链接，保存 `asset:` 引用，再通过 `page.reload()` 整页重载。后台与首页图片均由实例同源 API 提供，实际解码为 64 × 64，`filter: none`，原始颜色没有被反转；浏览器不访问书签目标或第三方图标服务。
- 已保存链接仍引用图库时，通过 UI 删除图库返回 `409`，提示原因且保留完整图库。随后只删除本轮新增链接，再删除本轮图库；原有图标库完整保留，本次图片 API 返回 `404`。
- JSON 图标包先含有效 SVG，再含带 `onclick` 的非法 SVG，服务器返回 `400`；完整图标包未落库，前一个有效图片也为 `404`，验证事务回滚无资源残留。测试只上传这些原始文件字节，不将非法 SVG 插入 DOM 执行。

成功路径的删除来自实际 UI。`finally` 中的 API 删除仅为异常清理后备，要求当前对象与本轮创建回执完全一致、ID 不属于原有链接或图库；发生其他修改则拒绝删除，并单独报告清理失败。测试不会批量清库、回写旧时间戳或重建导航。

可选 `--fetch-website` 通过显式“获取网站图标”操作请求服务端，不让浏览器访问外部网站。首轮中文默认 GitHub 目标返回 **HTTP 422、`favicon_unavailable`**，首轮英文未启用该分支。第二轮中文命中先前负缓存，仍为 `422`，界面显示“最近未找到支持的网站图标，请在缓存过期后重试，或直接导入图片。”；英文在 build3 上首次获取 GitHub 仍为 `422`。负缓存返回不表示重新进行了外网请求；GitHub 这几次结果均未进入成功资产或第二次正缓存校验。

额外的英文运行将 `WEBSITE_ICON_URL` 明确设为 `https://www.typescriptlang.org/`。服务端实际取得 `https://www.typescriptlang.org/favicon.ico`，规范化为 **48 × 48、`image/png`**，浏览器中的同源图片也真实加载成功。首次响应为 **`cached:false` / `stale:false`**，第二次为 **`cached:true` / `stale:false`**；二者资产 SHA 均为 `e7bcd79184133ab7ff275b29da19e3b0deef3bf746b53016bc96022d347a16a6`。该次运行完成了真实获取、显示及缓存复用，随后仍完成导入、保存、整页重载、引用冲突与原子回滚检查，并清理临时链接及图库。原 43 条链接、8 个分类、3 条收藏的全部字段和页面 revision `47` 保持不变。

成功或失败缓存只留在这两个独立验收副本；取消链接草稿不撤销这种缓存写入。TypeScript 正缓存按产品规则保留，未修改已有链接的图标，也没有为清理而直接改库。重复运行时第一次请求可能已经为 `cached:true`，应按报告的真实值记录，不能继续声称每次都是首次网络获取。上述成功不覆盖 GitHub 仍未获取成功的边界。

### 发布前补充验收：PostgreSQL 取消与关机修正

2026-10-19 后续补充验证发现：把已取消的请求 context 传给 PostgreSQL 专用持锁连接的 Ping，会让 pgx 丢弃该连接，导致后续正常请求锁存为 503。首次完整 race 的 PostgreSQL 集成 bootstrap 失败保留为失败记录，不能因为没有 DATA RACE 就记为通过。独立真实 PG 诊断确认了预取消调用之后连接关闭的生产风险；20 次 worker 取消夹具没有复现同样时序，因此不把该夹具推测写成首次失败的确定原因。
